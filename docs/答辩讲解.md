# 答辩讲解

## 用一句话介绍

我们把信贷违约预测模型做成一个可交互系统：先预测风险，再用 SHAP 解释因素，最后通过报告和情景对比辅助理解。

## 我负责什么

工具、LLM 智能层、训练编排和 Web 页面，以及规则检查 Agent、A/B 分流和情景对比。数据预处理、具体模型、调参、SHAP 和漂移检测的核心实现来自同学，我负责调用、适配及展示。

## 为什么先划分数据

如果先用整份数据填缺失、标准化或者筛选特征，测试集的信息会进入训练过程，评估会偏乐观。所以先固定训练、验证和测试集；只有训练集用 fit，另外两份和以后新申请都用 transform。

验证集用于早停、调参和选择分类阈值。测试集留到最后计算 AUC、KS、F1。页面的低/中/高风险区间是项目教学规则，与评估时优化的二分类阈值是不同用途。

## 训练和预测为什么一致

训练时把特征规则、填充值、编码器、标准化器、筛选结果、模型和列顺序一起保存。新申请交给同一个 InferenceService，按同一顺序处理。缺少的辅助字段使用训练集默认值，页面不会临时重新拟合模型。

## 衍生特征怎么讲

月收入 = 年收入 / 12；月供收入比反映相对还款压力；贷款收入比反映贷款金额相对收入的大小；信用利用率分箱帮助观察区间差异。分母为零时设为缺失，再由训练集预处理处理。

先用原始单位算这些比值，再标准化，避免拿标准化后的数值解释真实业务比例。

本轮增加了十一项通用业务候选，先在验证集比较，默认只保留等级和稳定就业两个新增标记。配合浅树、正则化和小型 MLP 后，四个模型的固定测试集 AUC 均提高；不是所有候选一起堆进去，也没有改标签或生成概率。树模型中简单放大某列数值通常不会提高重要性，页面展示的是训练学到的分裂收益。

## SHAP 怎么讲

SHAP 把模型原始输出分解为基线和各特征贡献。正值推动输出上升，负值推动输出下降。全局图看整体哪些因素重要，瀑布图和力图解释单笔样本。

树模型的原始输出通常是 log-odds，不能直接把 SHAP 的和当作违约概率。页面用模型 predict_proba 得到概率。如果选择 MLP 或融合，旁边的树 SHAP 只解释明确标注的子模型。

## LLM 怎么讲

ReportAgent 写报告，FeatureAgent 提建议，CaseAgent 分析错误案例，ComplianceAgent 按课程政策和附加规则逐条检查，返回并校验四字段 JSON。基本流程是整理上下文 → Jinja2 渲染模板 → 调用 DeepSeek → 解析返回内容。

没有密钥也能展示本地示例，但页面明确标注。LLM 失败不影响模型预测。特征建议只允许几种固定运算，不能执行模型生成的任意 Python。

计费统一放在客户端：读取服务端 usage，区分缓存输入和输出，按 API 实际响应模型对应单价计算人民币估算。流式需要 include_usage；用量不完整则待核实，不当作免费。账本只保存数字与模型、费率、时间，不保存问题、回答和密钥；估算不是账户实际扣费。

## A/B 怎么讲

申请编号经过 SHA-256 得到稳定的分组位置，再与 A 组比例比较。同一编号、同一比例会固定进入同一组。两种模型在同一批测试样本上比较，防止数据不同造成误判。

这里是离线模拟。没有真实还款结果时，分组人数或平均预测概率不能证明哪组业务收益更好。

## 情景对比怎么讲

复制一笔申请，改贷款金额、年收入、期限和利率，同时重新计算月供。两份输入交给同一个模型，对比概率和特征贡献。这是条件变化下的模型响应，不是因果分析，也不保证提高收入后风险一定下降。

## 建议演示顺序

1. 首页说明合成数据及四种模型。
2. 单笔预测提交表单，展示概率、瀑布图和力图。
3. 打开“7.2 政策合规检查”Tab，演示 LPR、年龄证明和贷款用途规则，说明三条规则是课程约定；真实 API 已配置，可按需要点击检查。
4. 情景对比把贷款金额改为另一数值，再计算一次。
5. A/B 页面改变分流比例，说明稳定分组。
6. 模型监控选择“模拟收入分布变化”，展示同学的检测结果。
7. LLM 助手底部查看最近一次、累计 Token 与人民币估算费用。

合成数据的 AUC 不高是因为信号较弱。这里主要展示完整链路和分工衔接，真实数据训练后的指标需要另行验证。
